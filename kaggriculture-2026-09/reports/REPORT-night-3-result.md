## 3. 重要修正：A/B 不能用"显示分"做

实测确认：
- API **不暴露单条提交的分数**（`publicScore` 恒为 `None`）；
- 榜单每队**只显示最新一条**提交的实时分（本队那一行的 `submissionDate` 始终等于最新提交）。

所以 A、B 只差 48 秒时，榜上只能看到 B，原计划的"同龄显示分对照"**做不到**。

**改用更直接的仪器**：`scripts/track_submission.py` —— 按提交 id 拉它的公开对局，直接统计
`games / W-L-T / 胜率 / 分差均值与中位数 / 对手平均天梯分`，并把每次采样存进 `data/submission_track.json`。
这测的是**真实天梯表现**，不依赖显示分，也不受"年龄衰减"干扰。

## 5. 判定规则（明早用）

1. 采样到两条线各 ≥30 局（预计 6–12 小时内达到）；
2. 比较 **胜率** 与 **对手均分归一化后的分差**（对手均分差 100 分以内才可直接比胜负）；
3. 若 A、B 胜率差 < 3 个百分点 → 以本地成对证据更强的 **B** 为主线；
4. 若某条线出现 `ERROR`/异常 → 立即用另一条替换；
5. **把胜出的那条"最后一个"提交**（因为显示分只认最新一条）——即若判定 A 更好，则重新提交 A 让它在榜上可见；否则让 B 保持最新；
6. 之后的运营规则：把胜出的那条按 **12–24h 节奏刷新**（前 200 名里 95/200 的提交在 24h 内）。
