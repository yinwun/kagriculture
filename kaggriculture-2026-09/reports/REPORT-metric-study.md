# 元问题研究:哪个本地指标能预测天梯?

日期 2026-09-14/15 | 脚本 `scripts/metric_study.py` | 原始数据 `data/metric_study.json`

## 动机

我们被本地指标坑过两次:
- `front_run`:本地对冠军 **92.5%** → 天梯 **−170 分**
- V40:本地对当时冠军 **40:0** → 天梯 **比冠军低 82 分**(2,572 vs 2,669)

所以必须回答:**哪个本地指标真正能预测天梯分数?**

## 方法

取 6 个**天梯结果已知**的 agent,各测一批本地指标(对 starter / V42 / V41 / aurax7-v5
各 20 种子),再算与天梯分数的 Pearson 相关。

| agent | 天梯终值 |
| --- | --- |
| v37+clamp | 2674.2 |
| v37 原样 | 2632.1 |
| V40+clamp | 2587.9 |
| fr | 2493.5 |
| fr_sort | 2242.8 |
| (V40 原样) | 缺(路径写错,未纳入) |

## 结果一:胜率类指标全部失效(地板效应)

**所有历史候选对新一代的胜率都是 0.0%**(vs V42 / V41 / aurax7-v5 全败)。
`win_v42base`、`win_v41`、`win_aurax7v5`、`win_starter` 的相关系数全部是 **0.000**
—— 因为方差为 0,这些指标完全没有分辨力。

## 结果二:金币/边际类指标相关性极弱

| 指标 | 与天梯分数的相关 r |
| --- | --- |
| margin_aurax7v5 | +0.399 |
| margin_v41 | +0.399 |
| margin_v42base | +0.390 |
| bank_v42base | −0.248 |
| bank_starter | **−0.176** |
| bank_v41 / bank_aurax7v5 | −0.311 |

n=6 时,r 需要约 **0.81** 才达到 p<0.05。所以**最强指标也只有 r≈0.4,完全不显著**。
更糟的是 `bank_starter`(最直觉的"对弱手能赚多少")相关是**负的**。

## 结果三:排序也对不上

| agent | 天梯排名 | bank_v42base 排名 | margin_v42base 排名 |
| --- | --- | --- | --- |
| v37+clamp | **1** | 3 | 5 |
| v37 原样 | 2 | 5 | **1** |
| V40+clamp | 3 | **1** | 3 |
| fr | 4 | 4 | 4 |
| fr_sort | 5 | 2 | 2 |

**没有任何一个本地指标复现天梯排序。**

### 一个额外发现:测量本身是"耦合"的

同一批种子下,对手的得分会随我方行为变化。例如 v37 原样对 V42 时对手约 86,200;
换成 v37+clamp 时对手涨到约 113,500。因为市场是共享的 —— 我方卖得凶,对手反而赚更多。
所以"对固定对手的自身金币"这个指标带有系统性污染。

## 结论

1. **我们手上没有一个可信的本地裁判。** 胜率类饱和、金币类弱相关、排序对不上。
2. 这解释了为什么本地 40:0 / 92.5% 的改动到了天梯会翻车 —— 不是运气问题,是指标本身无效。
3. **唯一可信的裁判是天梯本身**,而天梯的代价是每天 5 次提交 + 每个候选约 18 小时收敛。

## 对"磁带层优化"任务的影响(重要)

**不能**用这些本地指标去驱动磁带搜索 —— 那等于在噪声上爬山,会产出过拟合的候选,
而且每次验证要烧掉 1-2 天。

可行的两条路:

**路线 A(稳,慢):把天梯当作搜索回路。**
每天用 2 个槽位测 1 个变量(像 v37 那轮 clamp 的 A/B 一样),约 18-20 小时出结论。
按此节奏,9/30 截止前还能测 5-7 个假设。

**路线 B(先修仪器,再搜索):建立"强度匹配"的本地对手池。**
现在的问题是对手池要么太弱(胜率饱和)、要么强到我们全败(地板效应)。
需要的是**与我们同强度**(2,600-2,800)的多样化对手 —— 例如持续收录新一代公开 agent
(V42/V41/aurax7 及其后继),用 **40+ 种子**测自身金币,并把每个未来的天梯 A/B
结果回填成新数据点,持续校准这个指标。仪器修好之前,任何磁带搜索都是盲搜。

**建议:先做路线 A(零额外成本,吃满每天的提交额度),同时按路线 B 持续收录对手。
在指标被验证之前,不要投入大规模磁带搜索的算力。**
