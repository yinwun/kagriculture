## §2 我们的层做什么（机制 + 为什么有效）

### 2.1 引擎市场模型（这是全部收益的来源）

```
价格 = f(库存)        ← 纯函数，无随机、无均值回归
库存变化 = 我方卖出 + 对手卖出 − 城镇消耗 − 双方买入
城镇消耗：每 4 步一次（单品种商店 2 单位 / 其他 1 单位）
撮合：逐槽 / 逐单位 lockstep —— 双方看到同一「预撮合价」
```

**推论**：
1. 一大笔卖出会**自己把价格曲线走到底** ⇒ 分步/限速释放能卖更贵；
2. 商店消耗是**唯一把价格抬回来**的力量 ⇒ 按消耗速率限速就是"让价格回血"；
3. 槽位顺序决定你**和谁交错成交**（对手的大单在旁边时，冲击被分摊）。

### 2.2 五个改动及其价值（全部本地配对实测）

| # | 层 | 做什么 | 实测价值 |
|---|---|---|---|
| ① | **槽位搜索** | 用精确复刻器预演候选排布，取 max(我方收入 − 对手收入) | +597/+676（对旧冠军）；消融关掉 −57~64 |
| ② | **羊毛前卖** | 按商店消耗速率限速释放 | +264/+397；消融关掉 −248~282 |
| ③ | **末期草莓** | 第 13 天起同样机制 | +480（t=7.62）；消融关掉 **−436（t=−7.57）** |
| ④ | **末期牛奶** | 同上 | **+84/镇（+0.08%）**，4/4 面板为正 → 极小 |
| ⑤ | **drain-mult** | 释放上限倍数 ×1→×24 | **直接对测 +0.64%（+95 分，CI +67~123）**，但天梯未转化（§3.4） |

**机制验证方式（每个层都要过）**：单位数必须持平，收益必须全在**实现价**上。
例：drain×24 vs ×1 —— 羊毛 1,656 = 1,656 单位，价 156.29 vs 152.88；草莓 1,984 = 1,984，价 91.89 vs 89.79。

## §3 天梯机制（最反直觉、也最决定成败的部分）

### 3.1 三条硬规则（实测）

```
规则1：只追踪「最新 2 条」提交
规则2：榜面显示 = 两条中【较好的】那条  (不是最新那条)
规则3：被挤出窗口的提交 → 停止对局 → 分数【冻结】在那一刻
```

**规则 3 的杀伤力**：我们 5 天内提交 20 次，等于**反复把正在跑的线冻在半程**。

| 实例 | 停止时刻 | 局数 | 冻结时分数 |
|---|---|---|---|
| 56533839（shep_straw） | 09-26 23:39（被手动提交顶掉） | 277 | 2,403.1 |
| 56565204（shep_straw） | 09-26 23:36 | 151 | 2,208.3 |
| 56601548（shep_straw） | 09-27 09:34 | **38** | 2,124.3 |
| 56601533（shep_straw） | 09-27 08:36 | **22** | 1,918.5 |

⇒ **同一份代码：277 局 → 2,403；38 局 → 2,124；22 局 → 1,919。** 局数不足的读数不可信。

### 3.2 分数不是胜率的函数（关键证据）

| 线 | 局数 | wr20 | 对手均分 | 分数 |
|---|---|---|---|---|
| 56533839（×1） | 277 | **50%** | **2,321** | **2,403** |
| 手动#1（同代码） | 83 | **50%** | 1,870 | **1,771** |
| 手动#2（同代码） | 88 | **50%** | 1,863 | **1,802** |

**三条 wr20 都是 50%，分数差 600 分、对手池差 450 分。**
⇒ 分数由**你被放进哪个池子**决定，而池子由**爬升路径**决定（早期抽到强/弱对手）。

### 3.3 路径方差 ±300~400（同代码的落点）

| 同一份代码/近似代码 | 落点 |
|---|---|
| v3（旧底座+三层） | 2,642.7 / 2,272.5 / **1,802.4** / 1,770.6 |
| shep_straw（新底座+三层） | 2,403.1 / 2,208.3 / 2,124.3 / 1,918.5 |
| 公开原版（无我们的层） | 2,402.0 / 1,905.6 |

**⇒ 我们的 1,985 是"下尾的一次抽签"，不是构建水平。**

### 3.4 本地优势为何没在天梯兑现（drain-mult 案例）

```
本地（受控配对，同底座、唯一差别是旋钮）：
   ×24 vs ×1 = +630 币/局 = +0.64% 钱包 = +95 分 (t=6.55, CI +67~+123)   ← 强证据

天梯（同起点并行跑）：
   ×1 臂   ：对手池 ~2,321 → 停 2,403
   ×2 臂   ：对手池 ~2,13x → 停 1,988
   ×8 臂   ：对手池 ~2,13x → 停 1,947（近期胜率 27%）

⇒ 天梯侧没有兑现（甚至相反），可能原因：
   (a) 本地对测只打「自家谱系」⇒ 对多样化对手过拟合；
   (b) 极端释放上限在陌生对手前把价格打崩（近期边际 −998）。
   注：样本小、场子每天下移 ~45，**尚未定论** → 00:05 的 ×24 vs ×1 同起点实验就是判定。
```

### 3.5 场子在缩水

| 切点 | 09-21 | 09-27 | 变化 |
|---|---|---|---|
| top1% | 2,811 | 2,616 | **−195** |
| top5% | 2,617 | 2,344 | **−273** |
| top10% | 2,417 | 2,131 | **−286** |

⇒ **绝对分数的目标（2,500/2,650）是移动靶**；判位置要看 **rank / 与切点的差**。

### 4.1 必须守住的仪器纪律（血泪教训）

1. **配对对决是唯一有效仪器**；对 starter 调参/筛选**无效**（实测反例：plan_v0 对 starter 调优 ⇒ 对冠军 0/400）。
2. **"参数不同却逐字节相同" = bug 签名**，不是死旋钮。已抓过 4 次：
   - `_View` 缺 `town` 字段 ⇒ 每步抛异常 ⇒ 外层 `try/except` 静默退回原始磁带（整栈失效，−32,430）；
   - 生成的 agent 在定义前引用 `farmer` ⇒ 每步异常 ⇒ **钱包冻结在 3,000**；
   - `_RACE_PARENT` 与底座全局名冲突 ⇒ 每步递归；
   - 松散匹配 `"SHOPS = {"` 命中底座的 `_OR2_SHOPS` ⇒ 商店表被丢。
3. **不可比的数据不能用来下结论**（我犯过两次：拿冻结 38 局的读数比 90 局收敛读数）。
4. **计划改动会翻转第 6 天商店抽取**（RNG 与杂草共用）⇒ 只能整局配对，不能筛选。
5. 每个变体都要报 `layer_fallbacks / entry_fallbacks / race_errors = 0`。

## §9 我犯过的错误（供你复核我的结论时参考）

1. **拿冻结在 38 局的中途读数**（2,124）**比 90 局收敛读数**（1,988/1,947）⇒ 得出"倍数越高天梯越差"——**该结论已撤回**；
2. **用传递推算**（×1→×2→×8→×24 逐级相加得 +1.85%）当成直接测量 —— 直接对测只有 **+0.64%**（高估 2.8×）；
3. **反复重交**，把 5 条强线冻在半程（22–88 局），直接损失了它们的收敛读数；
4. **过早断言"2,650 不可达/可达"** 各一次 —— 前者基于旧底座的价格通道上限，后者基于错误标尺。

**因此：本手册中凡我不确定的地方都标了「推测」；凡结论都给了出处。你若发现新的反例，请以配对实验为准，不要以我的推理为准。**
